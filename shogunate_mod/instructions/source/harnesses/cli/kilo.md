# CLI Harness: Kilo

- Treat Kilo as an OpenCode-compatible role surface unless a project-specific Kilo rule says otherwise.
- Follow generated role instructions, explicit task files, and permission boundaries before generic coding habits.
- Keep outputs deterministic and easy to audit: changed files, verification command, result, and remaining risks.
- Avoid provider-specific assumptions; use Shogunate queues as the shared state.
- When behavior differs from OpenCode, report the difference instead of silently changing the workflow.
